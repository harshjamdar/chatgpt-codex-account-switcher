SAFEKILL & SWITCH - V5.1.1 TEST REPORT
22 November 2026

45 checks passed (12 focused, 22 launcher UI, 11 installer), plus native-app lookup.
Force termination tests used two disposable scratch executables named codex.exe.
Only the explicitly captured fixture was stopped. An uncaptured same-name fixture
was retained; identity changes and exited processes were safely skipped.
UI confirmation was cancelled while real native sessions were running, and every
captured baseline session remained alive. No real login/history files were changed.
A full force-quit of the user's live app was not executed because it would end
this chat. Post-stop launching still uses the existing production one-account guard.

SafeKill cannot guarantee that unsaved work survives force termination. It does
not delete saved history/login files. SQLite crash recovery and app-specific
recovery still depend on the native app. A protected or newly started session
can keep the switch queued rather than bypass the guard.
